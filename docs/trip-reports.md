# trip reports

a trip report is one page bundle: a markdown file you write, plus a photo manifest a
script generates. the theme turns that into:

- an overview map of the whole trip at the top, with each leg drawn by how you got
  there (sail, ferry, train, hike, ...) and featured photos pinned where they were
  taken
- a day list down the left rail (the toc column) that tracks where you are
- one section per day: prose in the main column, date/route/day map in the tufte
  margin, big photos inline, and a photo strip at the end of the day
- strava activity cards pulled from the site's `/fitness/` pages
- a lightbox that steps through every photo on the trip in time order

photo bytes never live in git. they're served from the media host
(`params.media.baseURL`, files.botwerks.net) and the page only carries object keys.

## the short version

1. curate: put the keepers in an apple photos album / lightroom collection, export
   both into one folder. keep title, caption and location metadata on export.
2. `./bin/trip-photos.py content/travel/<trip> --src <export folder> --dry-run`,
   check the per-day report, then run it again without `--dry-run`. it makes the web
   sizes, uploads them and writes `photos.yaml` into the bundle.
3. write `index.md`: front matter with your places, then one `trip-day` per day.
   `hugo new content travel/<trip> --kind trip` gives you a skeleton from the theme's
   archetype. to change its defaults for one site, copy it to that site's
   `archetypes/trip/index.md`; hugo prefers the site's copy.
4. for strava cards or tracks, run the strava sync so the activity has a `/fitness/`
   page, then `make serve` and look at it.

## bundle layout

```
content/travel/202609-italy/
  index.md        # front matter (places) + the report, one trip-day per day
  photos.yaml     # generated by bin/trip-photos.py, hand edits are kept
```

media for the trip lives on the media host. the key prefix is the `trips` entry in the
site's `.s3-media.conf` plus the bundle's folder name:

```
trips/202609-italy/<YYYYMMDD>/<photo-id>-thumb.webp     480px long edge
trips/202609-italy/<YYYYMMDD>/<photo-id>-display.webp   1600px
trips/202609-italy/<YYYYMMDD>/<photo-id>-full.webp      2560px
```

keys are permanent. a photo's key doesn't change once it's uploaded, so links to it keep
working (which is also why uploads are sent with a year-long cache header).

## front matter

```yaml
---
title: "italy, september 2026"
date: 2026-09-22               # the first day of the trip
type: trip                     # selects layouts/trip/single.html
summary: "rome, a week sailing the bay of naples and the amalfi coast, sorrento, rome."
timezone: Europe/Rome          # photo capture times are bucketed into days in this tz
tags: [2026, travel, italy, sailing]

places:
  rome:       { name: "rome",               kind: city,      lat: 41.9009, lon: 12.5016 }
  capri:      { name: "capri",              kind: port,      lat: 40.5560, lon: 14.2376 }
  nerano:     { name: "marina del cantone", kind: anchorage }
  campanella: { name: "punta campanella",   kind: waypoint,  lat: 40.5640, lon: 14.3180 }
  bomerano:   { name: "bomerano",           kind: trail,     lat: 40.6285, lon: 14.5446 }

mapViews:
  - name: "bay of naples"
    bounds: [[40.53, 13.88], [40.86, 14.62]]
---
```

| key        | required | what it does |
|:-----------|:---------|:-------------|
| `type`     | yes      | must be `trip`. |
| `date`     | yes      | the first day. "day 5" in a day heading counts from here. |
| `timezone` | yes      | IANA tz name, used by `bin/trip-photos.py`. a photo shot at 00:30 local belongs to the day it was shot in this tz, not utc. |
| `summary`  | no       | shown under the title. |
| `places`   | yes      | every place a `route` mentions. keys are what you type in `route=`. |
| `mapViews` | no       | extra buttons next to "whole trip" on the overview map, for when one far-flung stop squashes everything else. `bounds` is `[[south, west], [north, east]]`. |

### places

each place is `{ name, kind, lat, lon }`.

- `name` is what's shown on the map and in the margin.
- `kind` controls the marker:

  | kind        | marker | label |
  |:------------|:-------|:------|
  | `city`      | filled dot | yes |
  | `port`      | open dot | yes |
  | `anchorage` | open dot (square in the margin) | small |
  | `trail`     | dot in the hike color | small |
  | `waypoint`  | none | none. it only bends a leg, e.g. to route a sail leg around a headland instead of over it. |

- `lat` / `lon` are optional. leave them off and the position comes from your photos:
  the first day whose route *ends* at that place, averaged over the last three photos
  with gps from that day. that's where you ended up, which for a sail day is the
  anchorage. the margin flags these as "position from photos". if no day ends there,
  or that day has no photos with gps, the build fails and names the place.

## shortcodes

### trip-day

one per day, in date order. paired form for days you've written up, self-closing form
for days you haven't (yet).

```markdown
{{< trip-day date="2026-09-26" route="rome napoli procida ischia"
             mode="train ferry sail" title="termini to the boat" >}}
the 08:05 frecciarossa had us in napoli centrale at 09:30, plenty of slack for the
10:45 ferry to procida.

{{< photo id="dsc04310" >}}

checked in, provisioned, and made the first hop to ischia in the afternoon.
{{< /trip-day >}}

{{< trip-day date="2026-09-27" route="ischia capri" mode="sail" />}}
{{< trip-day date="2026-09-22" note="msp -> fco, overnight" />}}
```

| param   | required | meaning |
|:--------|:---------|:--------|
| `date`  | yes | `YYYY-MM-DD`. ties the day to its photos and sets the anchor (`#d-20260926`). |
| `route` | no  | space separated place keys, in order. one key = you stayed put. |
| `mode`  | if the route has legs | one per leg (`train ferry sail`), or one value for every leg. `sail`, `ferry`, `train`, `hike`, `walk`, `drive`. |
| `track` | no  | how the day's line is drawn. see below. |
| `title` | no  | heading for the day. defaults to the route. |
| `note`  | no  | a single line for days with no route (travel days, flights). |
| `strip` | no  | `false` turns off the photo strip at the end of the day. |

`track` options:

- *(unset)*: straight lines between the route's places (bent by any waypoints).
- `photos`: on a two-place day, the line runs through that day's photo positions in time
  order. good for days with no gps track, like a sail leg with photos all along the way.
  silly on a day with three photos.
- `strava:<id>`: the activity's route instead of lines between places. several
  activities: `strava:111,222` (give one mode per activity, or one for all). the margin
  shows strava's distance.

the self-closing form renders a one-line row (date, route, "no notes yet") but its legs
still go on the overview map. to write the day up later, switch it to the paired form.

the strip at the end of each day fills itself with that day's photos from
`photos.yaml` (minus `hidden` ones). you don't list them.

the margin for a written-up day holds the date, the route as a vertical list (mode and
distance on each leg), and a small map of that day. sidenotes and photo captions inside
the day stack up in the same margin underneath.

### photo

a big photo in the flow of the text. image in the main column, caption in the margin.

```markdown
{{< photo id="dsc04417" >}}
{{< photo id="dsc04417" caption="this caption, not the one in photos.yaml" >}}
{{< photo id="img_2516" wide="true" >}}
```

| param     | meaning |
|:----------|:--------|
| `id`      | photo id from `photos.yaml`. required. |
| `caption` | replaces the manifest caption for this one use. markdown is fine. |
| `wide`    | `true` spans the margin column too; the caption goes underneath. |

clicking it opens the lightbox. an unknown id fails the build with the page and id in
the message.

### strava

a route card for a strava activity: map with start/finish markers, distance, moving
time, elevation gain, pace, and a link to the activity's `/fitness/` page. works on any
page, not just trips.

```markdown
{{< strava id="20300220731" >}}
```

the card reads the activity's `/fitness/<date>-<id>/` page (written by the site's
`bin/strava-visuals.py`): the route is its `summary_polyline`, the stats are its front
matter. nothing is fetched from strava at build time, so the activity has to be synced
and emitted first. if it isn't there, the build fails and tells you to sync. on a trip
page, the day's photos with gps show up on the card's map as small squares.

### the usual

`sidenote`, `marginnote`, `image`, `youtube` etc. all work inside a `trip-day`.
markdown footnotes (`[^1]`) don't, because each day's body is rendered on its own; use
`{{< sidenote >}}` instead.

## photos.yaml

generated by `bin/trip-photos.py` in the site repo (see `bin/README.md` there). you edit
it to fix captions and to pick featured photos; the script keeps your edits when it runs
again.

```yaml
- id: dsc04417
  day: '2026-09-28'
  key: trips/202609-italy/20260928/dsc04417
  taken: '2026-09-28T09:20:00+02:00'
  lat: 40.543
  lon: 14.263
  camera: sony ilce-7cm2
  width: 2560
  height: 1707
  title: faraglioni
  caption: the stacks from the water, *after* the first wave of boats left.
  featured: true
  hidden: false
```

| field      | source | notes |
|:-----------|:-------|:------|
| `id`       | original filename, lowercased, no extension | `DSC04417.ARW` -> `dsc04417`. two files with the same id stop the script; rename one. |
| `day`      | capture time in the trip `timezone` | |
| `key`      | prefix + day + id | the theme adds `-thumb.webp` etc. |
| `taken`    | exif | phones record their utc offset; cameras are assumed to be on local time unless you pass `--clock-offset`. |
| `lat`/`lon`| exif gps | missing for most camera shots. you can add them by hand; the script keeps them. |
| `camera`   | exif make + model | |
| `width`/`height` | the full size | the lightbox needs these. |
| `title`    | xmp / iptc title | yours once set. |
| `caption`  | xmp / iptc description | markdown. yours once set. |
| `featured` | you | pins the photo on the overview map. |
| `hidden`   | you | leaves it out of the page without deleting it. |

captions are written in apple photos / lightroom (title + caption fields) so they travel
with the image. `photos.yaml` is the copy the site renders, and the place to fix a typo
without re-exporting.

## the map

- legs are styled by mode: sail dashed, ferry dotted, train/drive solid gray, hike/walk
  solid in the hike color.
- clicking a place jumps to the first written-up day that visits it; clicking a leg jumps
  to its day; featured photos open the lightbox.
- raster tiles come from `params.maps.tileURL` and are grayed out by the theme
  (`--tile-filter`: grayscale in light mode, inverted in dark) so they sit quietly under
  the routes. maps use whole zoom levels so the tiles stay crisp.

## theme config

```toml
[params.media]
  # where object keys are served from. no trailing slash.
  # falls back to the older params.mediaBaseURL if unset.
  baseURL = "https://files.botwerks.net"

[params.maps]
  # raster tile source for trip maps and strava cards. defaults to osm.
  tileURL = "https://tile.openstreetmap.org/{z}/{x}/{y}.png"
  attribution = "&copy; OpenStreetMap contributors"
  maxZoom = 18
```

every template that needs a media url goes through `partial "media-url.html" $key`
(the fitness photo carousel included), so the host is set in one place.

carto's basemaps would match the look out of the box but now want an api key. a
self-hosted protomaps file on the media host is the fallback if osm's tile policy ever
becomes a problem.

## files in the theme

| file | what |
|:-----|:-----|
| `archetypes/trip/index.md` | skeleton for `hugo new content <path> --kind trip` |
| `layouts/trip/single.html` | the page: title block, overview map, day rail, days, map data |
| `layouts/_shortcodes/trip-day.html` | a day section; records the day for the rail + map |
| `layouts/_shortcodes/photo.html` | inline photo |
| `layouts/_shortcodes/strava.html` | strava route card |
| `layouts/_partials/trip/photos.html` | loads `photos.yaml`, adds urls + rendered captions |
| `layouts/_partials/trip/strava-activity.html` | finds an activity's `/fitness/` page by `strava_id` |
| `layouts/_partials/trip/scripts.html` | photoswipe + map config + `trip.js` |
| `layouts/_partials/media-url.html` | object key -> url |
| `layouts/_partials/leaflet-lib.html` | loads leaflet once per page (fitness pages and trips) |
| `assets/js/trip.js` | maps, day rail, lightbox, strava card maps |
| `assets/css/_trip.scss` | trip layout, photo strip, card + lightbox styles |

leaflet and photoswipe load from cdns with sri, and only on pages that need them
(`.Store "hasTrip"` / `"hasMap"`, see `baseof.html`).

## gotchas

- **camera clock.** if the camera is still on home time, every photo lands on the wrong
  hour and maybe the wrong day. check the "photos per day" report from `--dry-run` and
  re-run with `--clock-offset MODEL=+HH:MM` (what you add to the camera's clock to get
  local time; MODEL is exiftool's Model tag).
- **apple photos export.** turn on "include location information" in the export dialog,
  and fill in title/caption in the info panel before exporting if you want them.
- **strava before build.** a `track="strava:..."` or `{{< strava >}}` for an activity
  without a `/fitness/` page fails the build. sync first.
- **narrow screens.** under 1000px the margin collapses: the route turns into one inline
  line above the prose, the day map is hidden, and photo captions move under the image.
